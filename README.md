# Disk Space Monitor

Приложение для Windows 10/11: значок в системном трее на .NET 8 и независимый агент Python 3 внутри WSL. Агент передаёт данные через JSON-файл рядом с `DiskSpaceMonitor.exe`; HTTP, порты, права администратора и sudo не нужны.

## Сборка и запуск

Требуется .NET 8 SDK для сборки. Для работы с WSL нужны установленный дистрибутив и Python 3 внутри него. Windows-приложение работает и без WSL.

```powershell
.\build.ps1
.\run.ps1
```

Готовая поставка без установки .NET на целевом ПК:

```powershell
.\build.ps1 -Publish
.\publish\win-x64\DiskSpaceMonitor.exe
```

В каталоге `publish\win-x64` вместе с EXE должен оставаться `wsl\agent.py`. `run.ps1` запускает EXE именно оттуда. Для автозапуска текущего пользователя: `.\install-startup.ps1` после публикации; для отключения: `.\uninstall-startup.ps1`. Автозапуск также переключается через меню трея. Приложение допускает только один экземпляр.

## Релизы и установка на другом компьютере

Как в соседнем проекте LockBlock, GitHub Actions создаёт релиз при отправке тега `v*`. Перед публикацией запускаются сборка и проверки. Релиз содержит два варианта для Windows x64:

- `DiskSpaceMonitor-win-x64.zip` — self-contained: распакуйте архив и запустите `DiskSpaceMonitor.exe`; устанавливать .NET не нужно.
- `DiskSpaceMonitor-win-x64-compact.zip` — компактный вариант: распакуйте архив, при необходимости запустите `install-dotnet.ps1` для установки .NET 8 Desktop Runtime, затем запустите EXE.

В каждом архиве есть `wsl/agent.py`, пример конфигурации и README. Для работы агента на целевом компьютере дополнительно требуются WSL и Python 3 внутри выбранного дистрибутива. Приложение не требует инсталлятора или прав администратора. Установка системного .NET Runtime для компактного варианта может запросить повышение прав.

Собрать оба архива локально можно командой `.\publish.ps1` или `publish.bat`. Они появятся в `release\`. Чтобы выпустить версию через GitHub Actions:

```powershell
git tag v1.0.0
git push origin v1.0.0
```

Скрипт `install-dotnet.ps1` проверяет наличие Desktop Runtime, затем использует WinGet или открывает официальный сайт Microsoft. Автозапуск приложения регистрируется отдельно для текущего пользователя через меню трея или `install-startup.ps1`.

## Конфигурация и данные

При первом запуске `config.json` создаётся **рядом с запущенным EXE**. Там же хранятся `history.csv`, `wsl-metrics.json`, запрос анализа и файл блокировки агента. Каталог приложения должен быть доступен пользователю на запись; не размещайте переносную копию в защищённом `Program Files`. Каждая отдельная копия EXE имеет свои данные. По умолчанию включены готовые локальные диски, а WSL-дистрибутив определяется автоматически. Пример всех параметров — [config.example.json](config.example.json). После редактирования конфигурации перезапустите приложение. `Drives` — список букв дисков в формате `C:\`. Пороговые значения измеряются в GiB. Уровни срабатывают при **строго меньшем** остатке; цвет трея: зелёный, жёлтый, красный, мигающий красный/белый для аварийного уровня. Отдельное уведомление показывает быстрый рост.

При запуске через `run.ps1` редактируйте `D:\projects\DirStat\publish\win-x64\config.json` или выберите **Открыть конфигурацию** в меню трея. Для WSL важны поля:

```json
"WslDistribution": "auto",
"WslEnabled": true,
"WslAgentIntervalSeconds": 5
```

Значение `auto` выбирает первый пользовательский дистрибутив из вывода `wsl.exe --list --quiet`, пропуская `docker-desktop`. Если нужно выбрать конкретный, замените `auto` его точным именем. Пути к JSON и агенту приложение определяет само. После изменения файла выйдите из приложения через меню трея и запустите его снова.

История записывается не чаще раза в 30 секунд. Удаляются только устаревшие строки истории; пользовательские файлы, процессы и данные WSL приложение не очищает. Если вы уже запускали раннюю версию, её данные в `%LOCALAPPDATA%\DiskSpaceMonitor` остаются нетронутыми. Для переноса скопируйте нужные файлы вручную рядом с новым EXE после выхода из приложения.

Двойной щелчок по значку открывает состояние. Окно можно закрыть: приложение останется в трее. В меню доступны обновление, перезапуск агента, анализ каталогов WSL, конфигурация, каталог данных, автозапуск и выход.

## WSL-агент

Windows-приложение определяет дистрибутив и запускает `wsl.exe -d <имя> -- python3 -u <путь к agent.py> --output <путь к JSON> --request <путь к запросу> --interval 5`; пути преобразуются командой `wslpath`. При недоступности дистрибутива или Python 3 отображается ошибка, повтор запуска производится с задержкой. При выходе дочерний процесс WSL завершается. Внутри WSL второй агент с тем же выходным файлом блокируется через `flock`.

Ручной запуск непосредственно в WSL:

```bash
python3 /mnt/d/projects/DirStat/publish/win-x64/wsl/agent.py --output /mnt/d/projects/DirStat/publish/win-x64/wsl-metrics.json --request /mnt/d/projects/DirStat/publish/win-x64/wsl-analysis-request.json --interval 5
```

Подставьте свои пути. Можно также указать выходной JSON в любом доступном каталоге Linux. Агент пользуется `os.statvfs('/')`, читает `/proc/<pid>/io` только для процессов текущего пользователя и выбирает процесс с максимальной скоростью записи. Ошибки доступа и исчезающие PID пропускаются. JSON версии 1 содержит время, hostname, размеры файловой системы, доступное пользователю место, свободные и резервные блоки, процент заполнения и данные процесса. Обновление файла атомарное через `os.replace`.

JSON также содержит список процессов текущего пользователя с PID, командой и скоростью записи, отсортированный по скорости. Если в момент измерения они не пишут на диск, агент возвращает нулевую скорость и не указывает «ведущий» PID. `du` запускается только по запросу из меню или при первом переходе WSL в критическое состояние, не чаще раза в 10 минут. Он анализирует `~/projects`, `~/.cache`, `~/.local/share/containers` (хранилище rootless Podman) и верхний уровень пользовательских каталогов. Результат появляется в таблице WSL после завершения анализа.

В окне WSL показана общая скорость записи процессов текущего пользователя, а во вкладке **«Пишущие процессы»** — только процессы с ненулевой скоростью. Соседняя вкладка содержит результаты последнего анализа каталогов.

## Что означают размеры

- **Windows-диск**: `DriveInfo` сообщает занятое и доступное место на разделе Windows.
- **WSL /**: агент через `statvfs` сообщает занятые блоки и доступное пользователю место внутри Linux ext4. Предел ext4 (например, 1 ТБ) — максимальная виртуальная ёмкость, а не объём, уже занятый на диске Windows. Резерв ext4 — разница между всеми свободными и доступными блоками.
- **`ext4.vhdx`**: путь и размер файла виртуального диска на Windows автоматически берутся из регистрации дистрибутива в `HKCU\Software\Microsoft\Windows\CurrentVersion\Lxss` (`BasePath` и `VhdFileName`). Windows также сообщает размер, реально выделенный этому файлу на диске, и свободное место на разделе с VHDX. Размер VHDX отличается от занятых блоков внутри Linux. После удаления файлов внутри WSL файл VHDX может не уменьшиться; приложение только показывает этот факт и не выполняет компактацию.

Колонка **«До упора»** и пороги для WSL используют меньшую из двух величин: доступное место внутри ext4 и свободное место на Windows-разделе, где лежит VHDX. Это оценка для роста данных с учётом накладных расходов. Скорость записи берётся из `/proc/<pid>/io` для процессов текущего пользователя; она не включает процессы других пользователей и может не заметить короткую запись между измерениями.

Скорость роста рассчитывается по истории за последние 5 минут; ETA показывается лишь при положительном росте. В первые минуты после запуска оценка может быть неточной. Устаревшие метрики WSL помечаются в окне, если агент долго не обновлял JSON. Размер VHDX может быть недоступен для некоторых способов установки WSL. Агенту нужны права на запись в выбранный каталог данных.

## Проверки

`build.ps1` собирает solution и запускает проверки порогов, роста, ETA и разбора JSON без внешних тестовых пакетов.

Если WSL доступен, отдельно проверьте чтение фактической скорости записи через `/proc/<pid>/io`: `wsl.exe -d Ubuntu -- python3 /mnt/d/projects/DirStat/tests/test_wsl_agent.py` (подставьте своё имя дистрибутива и путь к проекту).
