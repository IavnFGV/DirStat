# Disk Space Monitor

Приложение для Windows 10/11: значок в системном трее на .NET 8 и независимый агент Python 3 внутри WSL. Агент передаёт данные через JSON-файл в `%LOCALAPPDATA%\DiskSpaceMonitor`; HTTP, порты, права администратора и sudo не нужны.

## Сборка и запуск

Требуется .NET 8 SDK для сборки. Для работы с WSL нужны установленный дистрибутив и Python 3 внутри него. Windows-приложение работает и без WSL.

```powershell
.\build.ps1
.\run.ps1
```

Готовая поставка без установки .NET на целевом ПК:

```powershell
.\build.ps1 -Publish
.\publish\win-x64\DiskSpaceMonitor.exe
```

В каталоге `publish\win-x64` вместе с EXE должен оставаться `wsl\agent.py`. Для автозапуска текущего пользователя: `.\install-startup.ps1` после публикации; для отключения: `.\uninstall-startup.ps1`. Автозапуск также переключается через меню трея. Приложение допускает только один экземпляр.

## Конфигурация и данные

При первом запуске создаётся `%LOCALAPPDATA%\DiskSpaceMonitor\config.json`. По умолчанию включены готовые локальные диски и WSL-дистрибутив `Ubuntu`. Пример всех параметров — [config.example.json](config.example.json). После редактирования конфигурации перезапустите приложение. `Drives` — список букв дисков в формате `C:\`. Пороговые значения измеряются в GiB. Уровни срабатывают при **строго меньшем** остатке; цвет трея: зелёный, жёлтый, красный, мигающий красный/белый для аварийного уровня. Отдельное уведомление показывает быстрый рост.

В том же каталоге находятся `history.csv`, `wsl-metrics.json` и запрос анализа. История записывается не чаще раза в 30 секунд. Удаляются только устаревшие строки истории; пользовательские файлы, процессы и данные WSL приложение не очищает.

Двойной щелчок по значку открывает состояние. Окно можно закрыть: приложение останется в трее. В меню доступны обновление, перезапуск агента, анализ каталогов WSL, конфигурация, каталог данных, автозапуск и выход.

## WSL-агент

Windows-приложение запускает `wsl.exe -d Ubuntu -- python3 -u <путь к agent.py> --output <путь к JSON> --request <путь к запросу> --interval 5`; пути преобразуются командой `wslpath`. При недоступности дистрибутива или Python 3 отображается ошибка, повтор запуска производится с задержкой. При выходе дочерний процесс WSL завершается. Внутри WSL второй агент с тем же выходным файлом блокируется через `flock`.

Ручной запуск непосредственно в WSL:

```bash
python3 /mnt/d/projects/DirStat/wsl/agent.py --output /mnt/c/Users/USER/AppData/Local/DiskSpaceMonitor/wsl-metrics.json --request /mnt/c/Users/USER/AppData/Local/DiskSpaceMonitor/wsl-analysis-request.json --interval 5
```

Подставьте свои пути. Можно также указать выходной JSON в любом доступном каталоге Linux. Агент пользуется `os.statvfs('/')`, читает `/proc/<pid>/io` только для процессов текущего пользователя и выбирает процесс с максимальной скоростью записи. Ошибки доступа и исчезающие PID пропускаются. JSON версии 1 содержит время, hostname, размеры файловой системы, доступное пользователю место, свободные и резервные блоки, процент заполнения и данные процесса. Обновление файла атомарное через `os.replace`.

JSON также содержит список процессов текущего пользователя с PID, командой и скоростью записи, отсортированный по скорости. `du` запускается только по запросу из меню или при первом переходе WSL в критическое состояние, не чаще раза в 10 минут. Он анализирует `~/projects`, `~/.cache`, `~/.local/share/containers` (хранилище rootless Podman) и верхний уровень пользовательских каталогов. Результат появляется в таблице WSL после завершения анализа.

## Что означают размеры

- **Windows-диск**: `DriveInfo` сообщает занятое и доступное место на разделе Windows.
- **WSL /**: `statvfs` сообщает занятые блоки и доступное пользователю место внутри Linux ext4. Резерв — разница между всеми свободными и доступными блоками.
- **`ext4.vhdx`**: размер файла виртуального диска на Windows, если дистрибутив зарегистрирован в `HKCU\...\Lxss` и файл найден. Он отличается от занятых блоков внутри Linux. После удаления файлов внутри WSL файл VHDX может не уменьшиться; приложение только показывает этот факт и не выполняет компактацию.

Скорость роста рассчитывается по истории за последние 5 минут; ETA показывается лишь при положительном росте. В первые минуты после запуска оценка может быть неточной. Устаревшие метрики WSL помечаются в окне, если агент долго не обновлял JSON. Размер VHDX может быть недоступен для некоторых способов установки WSL. Агенту нужны права на запись в выбранный каталог данных.

## Проверки

`build.ps1` собирает solution и запускает проверки порогов, роста, ETA и разбора JSON без внешних тестовых пакетов.
